## 1. 核心概念与现实场景边界

聚焦 **直连、中转与专线宣传应怎样理解，哪些需要合同或实测依据** 的实际应用场景，必须立足《解析、路由和本地环境》的物理交付事实与客观约束。

从**本地 DNS 防投毒与 Fake-IP 拓扑架构**切入，在《解析、路由和本地环境》的通信链路中，必须开启 Fake-IP 模式并做本地 DNS 分流，彻底消除运营商劫持与远程解析延迟，守住稳定与隐私底线。

网络代理协议的技术演进，本质上是在“安全性（特征混淆）”、“性能开销（握手延迟与加解密吞吐）”以及“抗弱网能力（丢包重传）”之间所做的工程权衡。例如：古老的 Shadowsocks 协议加解密极度轻量，但抗特征检测能力弱；Vless Reality 实现了近乎完美的原生 TLS 伪装，但在弱网下受限于 TCP 队头阻塞；而基于 UDP 的新兴协议（如 Hysteria2、TUIC）通过暴力发包在恶劣丢包网络下实现了极佳的流媒体吞吐，但极易遭到部分地区运营商 QoS 的强力 UDP 阻断或限速。看清底层机制，才能看懂套餐背后的真实技术成本。

### 3.1 典型算例深入拆解

针对《直连、中转与专线宣传应怎样理解，哪些需要合同或实测依据》的本地 DNS 拓扑进行实操演算：
1. 抓包排查：发现该用户的客户端使用了传统的本地直连解析，向本地运营商 DNS 查询境外服务器，收到了被污染的伪造 IP（127.0.0.1）；
2. 拓扑优化：用户在客户端开启 **Fake-IP 模式**，并将境外分流规则强制绑定至远端节点代解；
3. 成果检验：DNS 响应延迟从原本的 120ms 下降至 **0ms 瞬时返回**，境外网站连接成功率从 55% 飙升至 **100%**，零成本解决了被运营商劫持的隐性网络故障。

### 3.2 决策边界与量化判定条件

本地网络准则：严禁在未开启防污染 Fake-IP 或远程代解的环境下运行核心业务；任何将国内全部流量无脑走代理导致 DNS 错乱的配置，均属于严重不合规网络拓扑。
